# Shinobi Arena v0.22.0

## Tournament podiums

- Completed events show Champion, First runner-up and Joint second runners-up. A single-elimination event without a bronze match has two semifinalists sharing third place; the interface states that explicitly. Two-player events show only the champion and runner-up. League standings and knockout placement remain separate.
- The completed Group 1 benchmark derives its podium from its existing bracket: Hidan is champion, Zetsu is first runner-up, and Sasori and Deidara share second runner-up. No additional fight or historical result is invented or changed.

## Read results without interruptions

- Tournament background polling no longer rebuilds cards or reloads the results view. Scroll position, keyboard focus, expanded sections and unfinished form input stay intact while reading.
- When the server has new data, the existing Refresh brackets button receives a New results badge and an accessible update label. Readers choose when to refresh; replay viewing and tab changes stop the old poll. Normal signup and organizer actions still refresh after the action completes.

## Splash-first launch

- The permanent play page is https://driaque.github.io/shinobi-arena/. It loads the branded splash independently of the sleeping multiplayer server. Canonical metadata and visible play links point there. Direct backend visitors receive a reminder and a recovery-code hint, while their current browser profile and settings remain untouched.
- Render's free-service loading page appears before our application can serve HTML when opening its backend address while asleep. Application splash code cannot replace that provider-controlled page. Bookmark the static play address for the intended launch experience. No paid hosting upgrade, automatic profile transfer, redirect or background keep-alive service is added.

## Compatibility

- Refresh for the updated viewer. Combat controls, protocol 6 and duel-0.20.0 rules are unchanged. Existing tournament scores, rewards, profiles, loadouts and archived fights remain compatible. Replay retention and database expiry limits continue to apply.
