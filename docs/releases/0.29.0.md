# Fabled Rivals v0.29.0

## Discord accounts

- Open Profile / sign in, or Arena → My profile. Guest play and existing recovery codes remain available.
- Link this profile to Discord preserves the current player ID, rating, history and tournament rewards. It does not copy progress between players. If Discord belongs to another profile, linking fails with an explicit explanation and leaves the guest profile intact.
- Continue with Discord on another device signs into that linked player. Switching away from an existing profile requires an explicit confirmation; profiles are never merged automatically. Keep a guest recovery code if you want to return to an unlinked guest later.
- Log out of this device revokes the current game session and closes sockets authenticated with it. Other devices remain signed in. Game sessions expire after 30 days, with up to ten sessions per player; Discord sign-in restores access afterward.

## Privacy and compatibility

- Request only Discord's identify scope. No server membership, messages, friends, email, bot installation or community-server access is requested. Store the Discord ID and display label privately; provider access/refresh tokens are not persisted or sent to the game client.
- Authorization uses state, a browser-bound HTTP-only cookie, S256 PKCE and one-time confirmation bound to the original game window. Provider secrets stay on the backend. Game sessions are opaque, hashed in storage and revocable per device.
- Existing player IDs, recovery credentials, ratings, rewards, fight/replay formats and combat rules remain compatible. Add account-link and session tables for both PostgreSQL and SQLite. Browser controls and saved loadout preferences remain device-local.

## Activation and limits

- Production needs a Discord developer application, its client ID/secret and the backend PUBLIC_ORIGIN. Register PUBLIC_ORIGIN/auth/discord/callback in Discord. Without healthy persistent storage and complete configuration, the game explains that Discord sign-in is unavailable and preserves guest access.
- Mock-provider browser tests exercise the full popup flow, linking, cross-device/mobile profiles, independent logout and conflicts. These do not prove production Discord authorization. Inspect the real configured flow before calling Discord sign-in live.
- Requires popups. Restarting the single game server invalidates in-progress authorization attempts; start again. Account unlinking/deletion and Discord community-server automation are not included.
