# Shinobi Arena v0.18.0

## Responsive movement and arena depth

- Fixes a render-interpolation bug that restarted its blend every simulation tick and could leave local movement chasing an old pose. Local play now renders the current simulation directly. Online snapshot interpolation uses consecutive authoritative snapshots rather than repeatedly blending an already delayed pose.
- The server coalesces queued movement axes to the latest input while preserving ordered action pulses, reducing stale held-movement delay after a network burst.
- Analog up/down now moves toward the rear/front of a shallow arena lane, independently of jumping. Horizontal double-pull dash remains. Jump and Crouch use dedicated actions. Keyboard depth movement is Z/L for P1, Num 9/Num 6 for P2, with existing W/S and Up/Down jump/crouch bindings retained.
- Melee, projectiles, ground fields and push collisions respect depth separation; the CPU tracks its opponent’s lane. Depth is authoritative and recorded in replays. This is a shallow 2.5D lane, not a free-roaming 3D arena.
- Walk cycles follow distance actually travelled, with alternating planted feet and raised recovery steps, rather than a fixed animation speed at every analog strength.
- Live fighter size is restored from 0.88 to 0.96, with matching body collisions. Shaded faces, fabric lighting, gloves, faction cloaks and character details improve readability. Old replays retain their recorded scale.

## Combat controls

- Equipped jutsus are visible by default in a persistent deck row with names, keys and cooldowns. Empty slots are omitted. Hold Charge there or G to recover chakra; Crouch is available beside it. The Jutsus menu remains available.
- The visibility checklist includes additional jutsu slots, Charge and Crouch. Existing saved layouts, hidden-button choices, opacity and custom bindings are preserved. Depth keys only migrate into unused bindings.
- Crouch + Guard continues to shield through blocked-hit recovery; use the Crouch action plus Guard on mobile, since analog down now changes lane.

## Akatsuki and sound

- 28 fighters: Pain, Konan, Kisame, Deidara, Sasori, Hidan, Kakuzu, Zetsu and Obito join existing Itachi. Akatsuki has a roster filter and distinct procedural portraits/models.
- 64 selectable jutsus include Shinra Tensei, Banshō Ten’in, Paper Storm, Paper Binding, Explosive Clay Bird and Clay Minefield. Other new fighters use shared, customizable training techniques as gameplay adaptations.
- Original ambient music layers a minor-key motif, bass/pads and percussion. Combat sound layers include impacts, heavy hits, metallic guards/parries, elemental effects, awakenings, landings and chakra cues. No anime soundtrack samples are included.
- Sound unlocks after a user gesture. Audio settings provide mute and separate music/SFX levels, saved on this browser. Hidden tabs suspend audio; local audio settings pause the fight. Online matches continue.

## Compatibility

- Refresh every device. Protocol 4 requires duel-0.18.0. Older replay snapshots/catalogs remain viewable. Online play remains server-authoritative; this update does not add rollback or eliminate network latency.
- Loadout limits remain seven jutsus, two weapons and four consumables. Profiles, ratings and existing loadouts remain valid. The free PostgreSQL database still expires November 27, 2026.

## Startup splash

- The static game entry shows a lightweight startup splash immediately, loads the game and polls the online server’s health while Render wakes. Failed readiness requests retry automatically for up to three minutes; Retry and Play Offline remain available. The splash never joins a queue or writes a result.
- Play Offline starts CPU/local/training without waiting for the server. The game is revealed only after its scripts finish loading. Native Render cold-start pages appear before app code can run; use the static Pages entry to see this custom splash during cold starts.

## Release history

- The game footer and latest notes link to Release History. Each available version has a permanent, readable notes page; current archived logs start at v0.13.0. The build discovers versioned notes automatically, so future releases appear without manually maintaining an index.
