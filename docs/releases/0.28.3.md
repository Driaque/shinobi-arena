# Fabled Rivals v0.28.3

## Dependable connection attempts

- Find opponent locks the current attempt immediately, including while loading a profile. Cancel search or a mode change invalidates pending work; a late response cannot unexpectedly connect you or join a queue.
- Concurrent requests for the same server share one profile request, avoiding competing guest profiles. Failed requests release the pending attempt so they can be retried; existing recovery codes remain intact.
- Profile failures, socket errors, connection timeouts and an unacknowledged previous connection restore editable lobby controls. The 15-second connection budget includes profile loading and waiting for an old socket to close.
- Capture casual/ranked selection when searching; changing the field while connecting cannot silently change that attempt's queue. Ignore old socket events and malformed message envelopes. Clear old latency and quality samples on disconnect.

## Controls and compatibility

- Use Cancel search while connecting or waiting. After an error, Find opponent retries. There is no automatic requeue that could unexpectedly start another fight.
- Combat rules, ratings, protocol, replay schema and saved profiles are unchanged. Network loss during an active fight still ends the connection; this patch does not resume an interrupted fight or change server forfeit rules.

## Verification and limits

- Lifecycle regression checks cover late profile completions, repeated join requests, cancellation, mode-reset equivalents, identity failure/retry, connection timeouts, delayed close acknowledgement, old messages, heartbeat loss and concurrent identity creation.
- Browser coverage includes cancelling a delayed profile request without a ghost queue entry, then retrying into a real desktop/mobile match. Passing emulated browser checks does not establish physical-phone performance or real-network latency tolerance. Those playtests and server-side reconnect design remain follow-up work.
